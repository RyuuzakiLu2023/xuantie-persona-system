> **状态**：🟡 草案（v0）· 拟议功能
> **归属**：玄铁记忆系统（XTMEM）子方案
> **实施条件**：⚠️ 待记忆系统本次大更新（spec-v1.0 演进）完成后评估再启动
> **发起**：龙崎（2026-08-27）· 玄铁起草

## 1. 背景与痛点

每次要升级 / 修改某个项目代码，都要**人肉把代码重新读一遍**才能恢复上下文——同一个项目反复啃，极度低效。根因不是"没有索引"，而是**索引跟不上代码变化**：读一遍写下的结论，代码下次一改就过时，又得重读。

**目标**：建一个「代码库活地图」——不用重读代码，**扫一眼索引就知道**项目结构、关键点、近期变更、坑。且索引要**能自动跟上代码变化**，而不是一次性吃一口。

## 2. 核心理念：注释即索引

玄铁已有 **AGENTS.md 注释规范**（总导游图 / 64 等号横幅 / 符号分工 / 契约模板 / 代码引用）。这些结构化的注释**本身就是代码库的地图**——不是装饰，是骨架。

因此不做"读代码理解再总结"（慢、易过时、靠 LLM 玄学），而是**写一个嗅探脚本提取注释**，把规范化的注释重新拼装成结构化索引：

- 注释是**按规范写的**（AGENTS.md 强制）→ 结构统一、可解析
- 注释更新 → 重跑脚本 → 索引自愈
- 扫的是**注释**不是代码逻辑 → 快、稳、不靠 LLM 重新理解

## 3. 注释模式 → 索引项映射

| 注释模式（已有规范） | 提取成 | 用途 |
|---|---|---|
| 总导游图（文件顶部"这文件干嘛/入口/依赖/给谁看"） | 文件名片 | 扫一眼知定位 |
| 64 等号横幅（`==== 模块 xxx ====`） | 模块切分点 | 结构骨架树 |
| 契约模板（docstring 接口/参数/返回） | 模块接口 | 调用关系 |
| 符号分工（`✅🔴🟠🟡🪦` 打在注释里） | 状态标记 | 坑/死代码/待办一眼可见 |
| 代码引用（`file:line`） | 交叉引用图 | 关键调用链 |

## 4. `codebase-map.py` 嗅探脚本

输入项目路径 → 输出结构化索引（JSON / MD）：

```
📁 目录树（按导游图/横幅切出骨架）
📌 文件名片清单（每文件导游图）
🧩 模块切分 + 契约接口
🚩 状态标记（🔴坑 / 🪦死代码 / 🟡缺陷）
🔄 最近 git 变更（谁改了啥）
```

- 一键跑，几秒出图
- 不碰代码逻辑，只扫注释 + git log

## 5. 与记忆系统的关系（为什么接进 XTMEM）

1. **索引存储**：结构化索引存进 **XTMEM**（每项目一个 `namespace`，打 `codebase-map` 标签），跨端共享、跨会话可查 → 本小姐扫记忆即回忆。
2. **仓库跟随**：同时输出 `repo-map.md` 跟项目走，方便直接扫文件。
3. **自愈机制**：`post-commit` git hook 或 **cron 定时**跑嗅探脚本 → 索引自动跟着代码更新，解决"会过时"的核心矛盾。

## 6. 与注释规范的硬约束（绑死）

- 前提：文件注释得**达标**（AGENTS.md 在管，写代码必带导游图/横幅）。
- 收益：注释写得好 → 地图自动准；注释偷懒 → 地图自动露馅（缺名片=注释不达标）。
- 效果：**注释合规性和代码可维护性绑定**——注释既是给未来的向导，也是地图的原料。
