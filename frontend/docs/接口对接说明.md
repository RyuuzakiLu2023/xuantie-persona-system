## 一、端点 × 视图对照（2026-09-02 重构后）

> ⚠️ 前端已重构为三视图：会话（主页）/ 差帖案 / 星渊图。下表是重构后的真实归属，
> 已对齐代码（src/lib/client.ts 的 api 对象是唯一网络出口，组件经 hooks/App 调用）。

| 端点 | 谁在用（重构后） | 形状 |
|---|---|---|
| GET /api/cockpit/state | 顶栏（活性灯/钟）+ 会话右栏（灯龛、推格、最近往来）+ 体征条 | CockpitState |
| GET /api/rooms | 会话左栏（石舫与横档：房→话题/轮次/待发言者） | RoomsRes |
| GET /api/room/{id}/context | 会话中栏气泡流（选中的房 + 话题） | RoomContext |
| POST /api/msg/send | ChatBar 投出 / 手机快回 / 完整递帖台（更多…） | SendReq/Res |
| POST /api/task/ack | 差帖案回执 + widget 卡片按钮（同一端点，契约合并） | AckReq/Res |
| POST /api/room/{id}/schedule | 群聊房间"开一轮" | ScheduleReq/Res |
| POST /api/widget | ⚠️ 前端目前【无】组件主动调它（卡片按钮走 /task/ack）——见 Q2 | WidgetReq/Res |
| GET /api/graph/memory | 星渊图（装置记忆点/灯间丝/渊谱叠层/实体名单） | MemoryGraph |

轮询节奏：useCockpit/useRooms = 2–5 秒；useGraph = 前者的 3 倍（图大，不需要那么新鲜）。
【不】自建 WebSocket——实时感来自动效编排（useFrameClock 本地 60fps 时钟对账）。

## 二、mock 行为备忘（接真后端时对照，别让行为漂移）

1. POST /api/msg/send 返回 queued 帖 + 登记一条命途；之后前端【只】靠轮询
   state.recent 看到它变化（waking→streaming→replied/acked/timeout）。
2. 流式回传 = 轮询间隔里累积的 stream 字段（逐句追加），前端逐字呈现。
   真后端若一次性给全文，前端会把整段当作"最后一帧"——观感会差，
   建议后端也按句追加（或前端按字符率插值，二选一即可）。
3. 超时（timeout）= 收件人 can_answer_now=false（Z指导行灯）或唤醒超过 deadline_s。
4. POST /api/task/ack 传 message_id 是差帖回执；若 message_id 是 widget id
   则是卡片按钮回调——mock 里两者都处理了（真后端需同样支持）。
5. send 时 visibility=private：响应里 content=null + redacted=true。
   ⚠️ 前端【不】接收私密正文是硬契约，不是约定俗成。

## 三、对契约的疑问（原始版 · 悬在这里等拍板）

> 下为交接时的原文疑问，逐条展开的「现状 / 前端依赖 / 建议」见 **第五节 给后端的拍板清单**。

Q1. 全局图谱的规模：GET /api/graph/memory 现在给的是 260 条记忆的"窗口"
（vitals.total=3214）。真后端一次给全量还是分页？前端画布上限 420 颗点

Q2. widgets 的推送源：POST /api/widget 看起来是"某 AI 主动推"，
那 GET 侧 widgets 列表挂在 /api/cockpit/state 里是否成立？
（现在 mock 是这样放的；若后端想把 widgets 独立成 GET /api/widgets，请改契约，
前端会跟上——【不】擅自假设。）

Q3. 差帖回执与卡片按钮共用一个端点（POST /api/task/ack），靠 message_id
指向不同类型对象区分。这个"按 id 类型分支"的语义是否打算长期保留？
若分开，请明确新端点路径。

Q4. 活性灯 liveness 的语义：契约只说"活性灯"，mock 里 0–1 驱动水面扰动。
后端打算给什么粒度？（进程心跳 / 近期事件率 / 各端聚合）请给一个可解释的定义。

Q5. 私密条数泄露面：rooms.topics[].private_count 这类"只给条数"的字段，
是否覆盖全部视图？(审计报告 O-9 提过条数差值存在性侧信道——前端只呈现
契约给的条数，侧信道的处置属于后端职责，列此备忘。)

Q6. Message.stream 的累积语义：轮询拿到的是"自创建起的全部追加"还是
"距上次轮询的新增"？mock 用的是前者（前端按长度去重）。真后端建议也前者，
否则轮询时序稍有抖动就会丢字。

## 五、给后端的拍板清单（Q1–Q6），每条给出：现状 / 前端依赖 / 建议

> 用途：把这 6 条直接转给后端即可。前端按约定【不】擅自改契约，等拍板后再同步。
> 共性建议：契约字段名与语义尽量别改——前端 contract.ts/endpoints.ts 是唯一出处，
> 改一次要全链路对账（见文件头上方「修改铁律」）。

### Q1 · GET /api/graph/memory 的规模
- **现状（mock）**：给 260 条记忆的「窗口」，`vitals.total=3214`；画布上限 420 颗点，超量按 heat+life 截断。
- **前端依赖**：直接吃 MemoryGraph（entities/memories/edges/bonds 一个响应）。若后端一次给全量（3000+ 条），
  前端先截断到 420 颗点——够看不是全量；若分页，前端要加视口采样。
- **建议**：一次性给「按热度+寿命排序后的窗口」（约 400–600 条）+ `vitals.total` 展示总量。这正是 mock 现在行为，
  后端照此前端零改动。**若要严格分页，请明确 GraphEdge 能否跨页存在**（前端画线需 source/target 都在当页）。

### Q2 · widgets 的推送源与归属
- **现状（mock）**：widgets 列表挂在 `GET /cockpit/state.widgets`；`POST /widget` 是「某灯主动推」；
  ⚠️ 前端目前**没有组件调 POST /widget**（卡片按钮走 /task/ack，见 Q3），widget 是 mock 预置。
- **前端依赖**：会话右栏「灯推上来的」直接渲染 `state.widgets`。若后端改成独立 `GET /api/widgets`，
  前端要加一条轮询腿、从 cockpit/state 删 widgets——改契约我会跟上。
- **建议**：维持 widgets 挂在 cockpit/state（少一轮询，且 widget 与活性灯/未读天然同源）。
  若产品想区分「灯推的格子」与「系统状态」再拆 GET /api/widgets，一拆两处同步。

### Q3 · POST /task/ack 的双义
- **现状（mock）**：`message_id` 传差帖 id = 回执；传 widget id = 卡片按钮回调，两种都处理。
- **前端依赖**：差帖案「回执」按钮与推格「拍板」按钮都走这一个端点（`api.ack`）。契约合并是故意的。
- **建议**：**长期保留「按 id 类型分支」**最省事。若要拆开（回执 vs 拍板），请给新端点路径（如 `POST /api/widget/act`），
  前端会同步拆分。**千万别只改语义不改前端**——否则差帖回执与卡片点击互相串。

### Q4 · liveness（活性灯）的语义
- **现状（mock）**：0–1 的数，驱动水面扰动幅度；有帖在链上走就往 0.6 以上顶，安静回落。
- **前端依赖**：只当「心跳」显示（顶部活性条 + 水面振幅）。粒度太细前端用不上，太糊看不出有没有活在干。
- **建议**：给一个**可解释**定义即可，例如「近期（近 1 分钟）正在唤醒/流式回传的帖数占比」。不需精确到每端心跳。

### Q5 · 私密条数泄露面（side-channel）
- **现状（mock）**：`rooms.topics[].private_count`、`Agent.private_count` 这类「只给条数」字段存在。
- **前端依赖**：只呈现契约给的条数（封蜡位），前端**没有**也不允许反推正文或做「申请查看」。前端零风险。
- **建议**：侧信道处置（避免条数差值被推断正文存在性）**属于后端职责**；前端只需把契约字段完整呈现。
  请后端确认这些「只给条数」字段覆盖全部视图（会话话题、灯龛、星渊图记忆点都要能拿私密条数）。

### Q6 · Message.stream 的累积语义
- **现状（mock）**：轮询拿到的是**自创建起全部追加**（前端按字符串长度去重）。
- **前端依赖**：stream 用于气泡「逐字/逐句浮现」（流式回传）。若后端改成「只给距上次的新增」，
  前端轮询时序稍有抖动就会丢字（前端没法可靠按序号拼接）。
- **建议**：**真后端也用「自创建起全部追加」**（最简单最稳）。若坚持增量，请给可靠的游标/序号字段，前端按 id 去重而非长度。

## 六、一个行为约定（非契约疑问，但影响观感）

**流式回传的节奏**：mock 是逐句累积 `stream`，前端逐字呈现。真后端若一次给全文，
前端会把整段当成「最后一帧」——观感是「突然整行蹦出来」，没有「她在边干边回传」的过程。
建议后端也按句追加（或前端按字符率插值，二选一）。
