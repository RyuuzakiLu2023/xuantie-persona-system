## #1 · 2026-09-02 · tsc 报 import.meta.env 不存在 / 找不到 node 类型

- 现象：npx tsc -b 报 `Property 'env' does not exist on type 'ImportMeta'` 与
  `Cannot find type definition file for 'node'`
- 根因：① Vite 的 import.meta.env 类型靠 `/// <reference types="vite/client" />`
  声明文件提供，项目里没建 src/vite-env.d.ts；② tsconfig.node.json 配了
  `"types": ["node"]` 但 @types/node 没装
- 修复：补 src/vite-env.d.ts（env 变量逐一声明）+ npm i -D @types/node
- 教训：Vite 脚手架的"隐形依赖"（vite-env.d.ts、@types/node）一省就炸；
  新工程先跑一遍 tsc -b 再写业务代码。

## #2 · 2026-09-02 · npm install 先于 package.json 存在时静默装空

- 现象：并行执行 install 与写 package.json，install 显示 "added 23 packages"
  但装的是空壳默认包
- 根因：命令竞态——install 读到的 package.json 是旧/空的
- 修复：先落 package.json 再 install；用 npm ls react 复核版本
- 教训：写文件与跑命令不要在同一个消息里并行——有依赖关系的动作要串行。

## #3 · 2026-09-02 · 纸面主题一行 CSS 变量手滑打成乱码

- 现象：tokens.css 里 `--line-1: #a89madd;`（混入字母 m、多一位 d）
- 根因：手写十六进制色值时拼错；浏览器会静默丢弃非法值 → 该变量在 paper
  主题下拿到 undefined，界面"看起来没坏但其实缺了定义"
- 修复：grep 全文件色值逐位核对 + 让 tsc/build 无法发现此类错（CSS 无编译期检查）
- 教训：CSS 变量拼错不报错只消失，改完主题后要在两套主题下都肉眼验一遍；
  色值集中放 tokens.css 的好处就是只有一处要 grep。

## #4 · 2026-09-02 · "为什么小D 顺、ZCode 老报错"——路由腿与兜底结构的差异（环境诊断）

- 现象：同样的 OmniRoute 网关（localhost:20128，node 进程，8-31 起跑）、
  同样的 gorouter/tabitoken 上游，小D 用着顺，ZCode 会话里频繁
  server_error / 超时感强
- 根因（三层，全部实测取证）：
  ① **腿不同**：ZCode 当前 provider 5212690e = api.tokenrouter.com/v1
  （glm-5.3-free）。实测 /models 秒回 200，但 chat/completions 一发 25s
  超时、第二发 20.7s 才回且 content=null 只吐 reasoning_content——
  free 池是慢池。对照组 deepseek-v4-pro 直接 403 欠费（余额 $0.000000）。
  ② **结构不同**：小D 的主干道是 wb(20128)，模型带前缀路由到
  gorouter/tabitoken + combo 兜底（kimi-main-fallback 实测 1.6s 秒回、
  gorouter 5.9s 通、tabiai 这条腿今天 40s 超时——但小D 有 fallback 链，
  一条腿瘸了换腿，用户无感）。ZCode 直连 tokenrouter 单腿，没有本地兜底。
  ③ ** OmniRoute 本地库是遗骸**：storage.sqlite 停在 7-21（1.7MB、全表 0 行），
  app.log 尾部全是 7-23 的 sql.js OOM 崩溃——本地桌面版早炸了，
  现在跑的 20128 是另一个 node server 进程（8-31 起），上游配置不在本地库里，
  在云端面板。
- 修复/建议：ZCode 要顺，两条路二选一：
  A（推荐，零成本）：把 5212690e 的 baseURL 改成 http://localhost:20128/v1，
  key 用 wb 的 sk-d5f…39ef，模型名走网关清单里的 `z-ai/glm-5.3-free`
  或更稳的 combo（kimi-main-fallback 1.6s / moa-trio）——
  蹭小D 同款多级兜底。
  B：tokenrouter 上充钱解 403，或换掉 free 模型。
- 教训：**"同一个网关"≠"同一条腿"**。排这类问题先画清楚
  client → provider 配置 → 网关 → 上游 的完整路径再对比，
  别被"我们都走 OmniRoute"骗了；free 池的 200 也是慢 200，
  /models 通不代表 chat 通。

## #5 · 2026-09-02 · alpha:false 的画布首帧是「不透明黑」，rAF 一被暂停就露出来

- 现象：在后台标签页（或 headless）打开页面，渊那一整块是纯黑 —— 采样画布像素，
  2000 个采样点只有一种颜色 `0,0,0`，一层水都没画
- 根因：装置构造完只 `requestAnimationFrame(loop)` 就收工，首帧交给 rAF 画。
  但页面不可见时浏览器会把 rAF 整体暂停 → 首帧永远没来；而 `getContext('2d',{alpha:false})`
  的画布初值是不透明黑，于是「没画」直接显示成「一块黑洞」，而不是主题底色。
  同一个坑还有两处变体：`resize()` 改 canvas.width 会清空位图（暂停时不补画就留黑）；
  `setRunning(false)` 后 `setData()` 进来的新事实也画不上去（切回前台第一眼是过期的水位）
- 修复：engine.ts 三处补画 —— 构造末尾直接 `draw()` 一帧；`resize()` 里 `if (!running || !raf) draw()`；
  `setData()` 末尾同款补画；`setRunning(false)` 时主动 `draw()` 把最后一帧定成静帧，
  并在复活时把 `last` 清零（否则 dt 巨大，粒子会被一次性甩飞）
- 教训：**「省电就停帧」的设计必须配「停之前先把画面画对」**。停帧的语义是「画面冻住」，
  不是「画面消失」；任何会清空/失效位图的动作（resize、换主题、灌新数据）在停帧态下都要自己补一帧。

## #6 · 2026-09-02 · React 同一批次里连点两下，后一下把前一下的改动吃掉

- 现象：递帖台上点收件人（玄铁）→ 紧接着点帖型（差帖），结果收件人的选中态没了，
  「投下」始终禁用；单独点任一格都正常
- 根因：SendDesk 的签名是 `onChange(d: Draft)`，组件内部 `set = (patch) => onChange({ ...draft, ...patch })`。
  `draft` 是这次 render 闭包里的旧值；两次点击落在同一个 React 批次里时，
  两个处理函数读到的是同一份旧 draft，后一个的 `{...draft}` 覆盖掉了前一个刚写进去的字段
- 修复：签名改成「只报补丁」`onPatch(patch: Partial<Draft>)`，合并交给 App 的
  `setDraft(d => ({ ...d, ...patch }))` —— 函数式更新保证每次都基于最新值
- 教训：**受控子组件不要自己拼整份状态**。子组件只说「改了哪几个字段」，
  合并永远用函数式更新交给状态持有者；`{...state, ...patch}` 出现在事件处理函数里就是待爆的雷。

## #7 · 2026-09-02 · 用 iframe 量桌面形态，headless 把 iframe 的事件循环整个冻住

- 现象：为了在窄窗口里量 1520px 桌面布局，把应用装进固定宽度 iframe。首屏渲染出来了，
  但之后一切不动：时钟停在某一秒、切视图没反应、`setTimeout` / `MessageChannel` / `rAF`
  全都一次都不触发（挂了 15 秒，计数器仍是空数组）
- 根因：headless 浏览器对不可见 iframe 做整体节流/冻结，React 的调度器依赖
  MessageChannel + timer，一起被冻 → 组件永远提交不了下一次更新。
  这是测量环境的限制，不是应用的 bug
- 修复：改用 CDP 的 `Emulation.setDeviceMetricsOverride` 直接改顶层视口，
  页面是真的在跑；输入走 `Input.dispatchMouseEvent` / `Input.insertText` 真实管线
  （顺带解决另一个坑：用 JS 合成 `new Event('input')` 改 React 受控 input，
  DOM 的 value 变了但 React 的 props.value 仍是空 —— React 19 只认真实输入事件序列）
- 教训：**量界面要用浏览器的调试协议改视口，不要用 iframe 套壳**。
  遇到「渲染出来了但之后全不动」，先验 timer/rAF 有没有在跑，别去猜业务代码。

## #8 · 2026-09-02 · grid 轨道默认 min 是内容宽 —— 一个横向可滚的钮组顶宽整页

- 现象：手机形态（430px）整页可以左右拽，文档宽 483 > 视口 430；查下来 191 个元素越界
- 根因：顶栏是 `grid-template-columns: 1fr auto`。`1fr` 的下限是 `auto`（=内容宽），
  而视图钮组虽然设了 `overflow-x:auto`，它的内容宽 459px 仍把轨道撑到 459，
  顶栏跟着变 483，整页横向溢出。附带一个：`.clock` 被设成 0 宽却仍占一条轨道的 min
- 修复：`grid-template-columns: minmax(0, 1fr) auto` + 给可滚容器补 `min-width: 0`，
  `.clock` 在窄屏用 `display: none` 真正移出布局
- 教训：**flex/grid 里任何「内部可滚」的子项都要写 `min-width: 0`**（grid 轨道再配 `minmax(0, 1fr)`）。
  排横向溢出的手法：逐个 `display:none` 二分，看 `documentElement.scrollWidth` 什么时候回落。

## #9 · 2026-09-02 · 反馈写在「用完就关」的面板里，等于没有反馈

- 现象：检索打完光柱，面板自动关闭，「上一道：……在精炼层就照到了」这句话跟着一起消失。
  库主看到一道光闪过，不知道它扫到了哪一层
- 根因：回话 JSX 挂在检索面板内部（`probeOpen && ...`），生命周期跟面板绑死
- 修复：把回话搬到渊上的注解层（`.probe-said`，与降级说明同一个 `notes` 槽），
  面板关掉它还在，就贴在光柱旁边
- 教训：**动作的结果不能与触发它的容器同生命周期**。凡是「提交后关闭」的浮层，
  结果一律要落在浮层外面的持久区域；同款检查也适用于降级说明 ——
  图谱这条腿断了要贴在渊上（记忆点在四个视图里都看得见），不能只写在某一个面板里。

## #10 · 2026-09-02 · 切主题后装置总慢一拍换材质 —— 子组件 effect 比父组件先跑

- 现象：点主题钮，界面（DOM/CSS）立刻换色，但渊（Canvas 装置）的底色永远是上一套
  主题；连点两下才跟上。验收脚本断言主题切换时抓画布 (2,2) 像素，两套主题各测一次
  —— 第一次测出来的其实是『旧主题的画布 + 新主题的 DOM』，误判为通过
- 根因：useTheme()（App 里）把 data-theme 写进 documentElement 是在 App 的 effect 里；
  AbyssStage 监听 theme prop 的 effect 属于子组件。**React 里子组件的 effect 先于父组件**
  执行 → 子组件 refreshPalette() 读 getComputedStyle 时，父组件还没把 data-theme 写上去
  → 装置取到旧主题的令牌。于是每次切换，装置都画成『上一次』的材质
- 修复：AbyssStage 的主题 effect 把 refreshPalette 推迟一帧（requestAnimationFrame 后再读），
  那时父组件的 effect 已经提交，DOM 上是新主题
- 教训：**读 DOM 状态（getComputedStyle / dataset）的 effect，如果写入方在父组件，
  必须考虑 effect 执行顺序（子先父后）**。要么推迟一帧读，要么让写入方在 render 同步阶段
  就写。另：验收断言要『先切过去、再采样』，别让上一轮的状态漏进断言里。

## #11 · 2026-09-02 · 主页重构为会话窗口：从『四视图共用一个渊』改成『渊独占星渊图页』

- 现象/决策：库主拍板——主页以会话/聊天窗口为主；渊（星图）撤出主页，独占一个页面。
  原架构『AbyssStage 常驻、四视图共享、切视图只换面板』不再适用
- 处理：视图改为 chat（主页=会话）/ task（差帖案）/ star（星渊图）三个；
  AbyssStage 只在 star 视图挂载。装置卸载重挂的因果由 mock 状态承载（数据不丢），
  纯视觉动画（涟漪、上浮）在重挂时会重放一遍 —— 这是『独占页』的取舍
- 教训：**架构原则（一个装置常驻）服务于产品形态（渊永远在视野里）**；产品形态变了，
  原则要跟着变，并显式写出取舍。原 spec 的验收脚本也要同步改（视图键位、断言选择器全变）
