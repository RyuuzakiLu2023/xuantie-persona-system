### 验收怎么跑

    npm run build
    npx vite preview --port 5300 --strictPort     # 另开一个终端
    npm run verify

  脚本用 CDP 驱动真实 headless Chrome，桌面 1520x940 与手机 430x880 两轮 + 三态一轮，
  逐条打印 PASS/FAIL 并以退出码表态（0=全过）。断言看的是「它说了什么」而不只是
  「元素在不在」—— 文案错了照样报 FAIL。

### 这一轮修掉的实质缺陷（详见 错题本.md #5–#9）

| # | 缺陷 | 影响面 |
|---|---|---|
| #5 | 画布首帧交给 rAF，页面不可见时 rAF 被暂停 → 渊是一块纯黑 | 后台标签页打开必现；resize/换主题/灌新数据在停帧态同款 |
| #6 | 受控子组件自拼整份 draft，同批次连点两下互相覆盖 | 递帖台点了收件人再点帖型，收件人丢失、投不出去 |
| #8 | grid `1fr` 轨道下限是内容宽，横向可滚钮组顶宽整页 | 手机形态整页可左右拽，文档宽 483 > 视口 430 |
| #9 | 检索回话写在「打完就关」的面板里 | 光柱闪过但不知道扫到哪一层；降级说明同款（已一并搬到渊上） |

（#7 是测量方法的坑，不是应用缺陷：headless 会冻结不可见 iframe 的事件循环，
故验收改走 CDP 改视口。）

## 给下一手的叮嘱

- engine.ts 是参考实现不是死稿：类方法=接口设计，实现可重写，概念不许重写。
- 私密正文零下发是硬契约（fixtures 与 mock 都已守，别在 UI 层破例）。
- 注释风格按 AGENTS.md（64 = 横幅导游图、/* */ 禁 //、外号表）。
- 改完 UI 一律跑 `npm run verify`；新增交互就往 verify-ui.mjs 里补一条断言，
  断言写「它说了什么」（见该文件铁律 1）。
- 停帧态补画那三处（engine 的构造 / resize / setData）别删：删了就是错题本 #5 复发。
- 界面美学轮的方向（库主口径）：武侠/仙侠中国风，华丽在纹与质不在光晕 ——
  可参考 docs/设计说明.md 原则 2/3 与 tokens.css 的语义色配额；系统有 楷体/隶书/宋体
  可用（题名/匾额/落款），零 Emoji 硬底线不变。界面打磨完务必重跑 npm run verify。
