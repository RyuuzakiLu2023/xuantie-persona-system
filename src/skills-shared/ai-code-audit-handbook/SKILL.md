# AI 代码审计手册（实战版）

> 母本：`<PROJECT_ROOT>/new/AI代码审计方法手册.md`（完整命令组与实战案例在母本，本 SKILL 为执行纲要）。实战来源：aiduMEI v19 五轮审计 + mem0-enhanced 插件全量审计。

## 审计十诫（每次开工前默诵）

1. **文档是声称，代码是事实**——结论以 file:line 为证，不照抄 README/CHANGELOG
2. **每条发现必须带证据**：`文件:行号` + 一句代码事实，否则不算发现
3. 分开"作者自述"和"独立复核"，别让自述冒充结论
4. **先建对账基线**：把文档声称的关键数字/机制列成表再逐条核验
5. 严重度分级：🔴致命（卖点不存在/数据丢失/可利用漏洞）> 🟠严重（数值/接口不符）> 🟡缺陷（逻辑 bug）> ✅真实
6. **死代码是重灾区**：grep 调用点，有实现零调用都是可疑项
7. 区分"原创 vs 现成"：对照上游官方文档/包，防止把依赖自带功能当项目功劳
8. 修没修要看代码："已修复"≠修复了，逐条回验+实跑测试
9. 诚实：没核验的标"未核验"，报告宁缺毋滥
10. 留痕：记录审计对象 commit/时间/覆盖范围

## 阶段流程（按序执行，每阶段有检查表）

### 阶段 0 · 准备与摸底
拿代码（浅克隆/本地，**路径含空格必须加引号**）→ 摸规模（文件数/行数/最大文件 TOP/端点数）→ 读文档提炼"声称清单"（对账底稿）→ **插件类项目必做**：识别宿主/插件关系，两个根都拿到，列"声称 patch 的宿主类与方法"清单。

### 阶段 1 · 文档对账（声称 vs 真实）
模块切 4–6 块 → 每块核验（子代理可用则派发，带必读文件+声称清单+统一输出格式）→ **主代理亲自抽查 3–5 条防幻觉** → 交叉验证升级（≥2 独立子代理命中=可信升一级；🔴级必须亲手复验）→ 死代码核查：

```bash
# 精确判定：外部调用 = 全仓命中 − 定义文件命中；剩 0 = 死代码
grep -rn "funcName" <repo> --include=*.py | grep -v "定义文件"
# 模块级死判定：从未被 import = 整模块半成品
grep -rn "import scoring\|from .scoring" <repo> --include=*.py
```

原创 vs 现成：WebSearch 查上游文档；查不到时 `pip download <pkg>==<ver>` 解包 grep，比文档硬。

### 阶段 2 · 修复复审
新 commit → CHANGELOG 自述转核验项 → 逐条 grep+Read 判断真修/修过头/引新问题 → 实跑作者测试对照声称数字。判定：✅真修复 / 📐诚信对齐（删措辞非改码）/ ❌漏修 / ⚠️遗留 / 🔵澄清。

### 阶段 3 · 架构臃肿度
量化扫描：超长文件 TOP / 端点数 / 纯 re-export 门面 / star-import 链 / 重复实现 / 品牌词密度 / 后台线程数。输出"可安全精简清单"（按收益/风险排序，每条带具体一刀动作）。

### 阶段 4 · 安全面（记忆系统必查）
- **攻击面**：鉴权中间件豁免名单前缀绕过 / 默认密码回退 / 危险端点未鉴权清单 / 密钥泄漏
- **注入**：存储型 prompt 注入（写入无过滤→落库→召回拼接无边界）；SQL 拼接（f-string 进 execute 逐个看）；FTS MATCH 参数化；LLM 判定污染
- **★ 攻击样本实跑（静态 grep 只能证"有没有"，证不了"防不防得住"）**：写最小脚本直调检测函数；样本组 = 正常对照 + 原文注入 + ≥4 变体（同义/中文/全角 Unicode 同形/编码）+ 边界。**mem0 实战：6 样本只拦 1，4 个简单变体全穿透——黑名单正则缺一个变体就是系统性绕过**。Windows 坑：`py -X utf8`，结果写文件再 cat
- **★ 插件 patch 靶点验证（monkey-patch 项目头号死因）**：①靶点存在性（宿主里 grep 类/方法）②签名逐参匹配 ③**属性串味**（patch 里每个 `self.xxx` 拿去宿主类 `__init__` grep——mem0 实战：`self._client` 不属于被 patch 类 → 必 AttributeError → except 吞 → 静默失效 0% 生效）④版本错位按实际宿主核验 ⑤回退路径当主路径审 ⑥防重入标记时序 + unregister 还原

### 阶段 5 · 数据一致性
跨库写入无事务（每步失败抛错还是静默吞）→ 并发写 SQLite（WAL/busy_timeout/每线程连接）→ 单例线程安全 → 软删副本同步（幽灵记忆）→ 崩溃恢复/迁移幂等。

### 阶段 6~9 · 性能 / 测试质量 / 部署真实性 / 代码质量
N+1 查询 / 同步阻塞 / 无界增长；skip+mock 占比与**关键路径 0 覆盖**；Dockerfile 绑定与 README 验证命令在目标平台是否真能跑；**静默吞异常三分类**（except 总数 vs debug 吞 vs pass 吞 vs warning/error——>20% 静默吞 = 故障藏水下）。

## 输出规范

每模块：概述 / ✅真实 / 🔴致命 / 🟠严重 / 🟡缺陷 / 🪦死代码 / 数值对账表。全项目报告：一句话结论+评分 → 文档对账 → 架构 → 安全 → 数据一致性 → 其余 → 修复路线图（ROI 排序）→ 审计范围方法。**实测记录必写**（实跑命令+输出），"实测"与"代码推断"分开标注。

## 子代理派发模板

```
你是代码审计员，审计 <项目> 的 <模块>。仓库根：<绝对路径>。
【必读文件】（逐个 Read 全文，不要只扫）
【文档声称，逐条核验真伪】（列出声称+核验要点）
【输出格式】概述/✅/🔴/🟠/🟡/🪦死代码/数值对账，每条带 file:line。
只返回审计结论，不要修改任何文件。
```

插件类项目 prompt 必带【背景】：插件根+宿主根+patch 靶点清单。子代理不可用时主代理亲自跑全流程。

## 命令速查（高频）

| 目的 | 命令 |
|---|---|
| 死代码精确判定 | `grep -rn "func" . --include=*.py \| grep -v "定义文件"` |
| patch 靶点 | `grep -rn "class X\|def y" <宿主根> --include=*.py` + self 属性核对 |
| 攻击样本 | 最小脚本+4 变体样本组，`py -X utf8` 跑 |
| 上游实证 | `pip download <pkg>==<ver> -d /tmp/x` 解包 grep |
| 静默吞三分类 | `grep -rnE "except Exception" . -A1` 分头数 debug/pass/warning |
| SQL 拼接 | `grep -rnE 'execute\(f"\|execute\(.*\+ ' . --include=*.py` |
